# HP Seasons: тренажёр правил

Обучающий сайт для игроков ролевой игры [hp-seasons.ru](https://hp-seasons.ru/). Правила подаются в виде тематических тестов с объяснениями ответов и в виде справочника.

Сайт полностью статический (Vite + Vue 3 + TypeScript), регистрации нет, настройки хранятся в `localStorage` браузера.

> **Важно: ТЗ.** Полное техническое задание лежит в [`docs/SPEC.md`](docs/SPEC.md). Любое изменение или дополнение требований **сначала** вносится туда (с записью в «Историю изменений»), и только потом в код. По этому файлу сайт можно воссоздать заново на любой модели. См. также [`AGENTS.md`](AGENTS.md).

## Быстрый старт

Нужен Node.js 20+.

```bash
npm install
npm run dev        # dev-сервер; перед стартом контент собирается автоматически
npm test           # юнит- и компонентные тесты (Vitest)
npm run typecheck  # vue-tsc --noEmit
npm run build      # статическая сборка в dist/
npm run preview    # посмотреть собранный сайт
```

Только собрать JSON из контента: `npm run content` (результат в `public/data/`, в git не хранится).

## Деплой

Результат `npm run build` — папка `dist/`. Её можно выложить на любой статический хостинг (GitHub Pages, Netlify, Cloudflare Pages и т. п.). Используется hash-роутинг (`#/rules/spells`), поэтому настройка серверных редиректов не нужна.

По умолчанию `base` равен `./`, сайт работает из любой подпапки. Если нужен абсолютный путь, задайте его переменной окружения:

```bash
BASE_PATH=/hpseasons-learning/ npm run build
```

## Как добавлять контент

Контент лежит в `content/`:

- `content/topics/<id>.yaml` — темы с вопросами;
- `content/rules/<id>.md` — статьи справочника.

База содержит 566 вопроса по 9 темам, 7 общих справочных статей и отдельный Монстробук из 67 полных карточек с 68 изображениями. Вопросы основаны на открытых правилах hp-seasons.ru и предоставленном Монстробуке. У каждого вопроса есть объяснение и ссылка на соответствующий раздел; для внешних правил также указан первоисточник. На один проверяемый аспект допускается не более трёх вопросов во всей базе. Источники и неоднозначности перечислены в [content/SOURCES.md](content/SOURCES.md).

### Тема с вопросами

```yaml
id: spells                  # латиница, цифры, дефис; совпадает с именем файла
title: Заклинания
description: Формулы, жесты и условия колдовства
order: 1                    # порядок на главной
questions:
  - id: q1
    type: single            # один верный вариант: отвечается одним кликом
    prompt: Что обязательно должно быть у персонажа, чтобы колдовать?
    options:
      - { id: a, text: Волшебная палочка, correct: true }
      - { id: b, text: Книга заклинаний }
    explanation: Для колдовства нужна волшебная палочка.
    rule: spells#casting                  # необязательно: статья#якорь
    source: https://hp-seasons.ru/...     # необязательно: первоисточник

  - id: q2
    type: multiple          # несколько верных; сколько выбрать — считается по correct
    prompt: Какие заклятия непростительные?
    options:
      - { id: a, text: Империус, correct: true }
      - { id: b, text: Круциатус, correct: true }
      - { id: c, text: Люмос }
    explanation: ...
```

Вопросов со свободным вводом текста (`type: text`) нет: сборка контента завершится ошибкой. `id` вопросов достаточно делать уникальными только внутри темы.

Правила проверки:

- `single`: ровно один вариант с `correct: true`.
- `multiple`: выбранное множество должно в точности совпасть с верным. Подсказка «Выберите N варианта» строится из числа верных вариантов.
- Порядок вариантов на экране зависит от переключателя «Перемешивать варианты ответов» (по умолчанию включён); порядок в YAML на проверку не влияет.

### Режимы теста

Перед каждым тестом открывается стартовый экран:

- **Три режима: все вопросы в одинаковом порядке, все вопросы в случайном порядке или 20 случайных вопросов.** Для одинакового порядка можно задать включительный диапазон «с / по» (по умолчанию 1–N); принимаются только целые номера в пределах списка, начало не больше конца. Если в теме не больше 20 вопросов, «20 случайных» берёт все, вперемешку.
- **Режим обучения**: правильные ответы проставлены сразу, разбор виден сразу. Выбор не запоминается: по умолчанию режим выключен.
- **Тест по всем темам** (карточка на главной, `#/all`): вопросы из всех тем идут в порядке, заданном выбранным режимом.

Результаты «все вопросы» и «20 случайных» сохраняются отдельно.

### Статья правил

```markdown
---
id: spells          # совпадает с именем файла
title: Заклинания
section: Магия      # раздел в справочнике
order: 1
---
Вводный текст.

## Условия колдовства {#casting}

Текст. Заголовки `##` и `###` получают якоря: явный `{#casting}` или автоматический из текста.
```

Ссылка на статью из другой статьи: `[текст](#/rules/spells?anchor=unforgivable)`.

### Типичные ошибки валидации

Если в контенте ошибка, `npm run dev` и `npm run build` останавливаются, а в консоль выводится файл и путь до поля:

```
Ошибки в контенте (2):
  - topics/spells.yaml: questions[0].explanation: Required
  - topics/spells.yaml: questions[2].rule: статья «nope» не найдена
```

| Ошибка | Причина |
|---|---|
| `explanation: Required` | у вопроса нет объяснения |
| `у вопроса single должен быть ровно один верный вариант` | ни одного или несколько `correct: true` |
| `дублируется id вопроса / варианта / темы` | повторяющиеся `id` |
| `статья «…» не найдена`, `нет якоря «…»` | `rule` ведёт на несуществующую статью или якорь |
| `Unrecognized key(s)` | опечатка в имени поля **или запятая в тексте варианта** |
| `id: должен совпадать с именем файла` | `id` отличается от имени файла |

**Запятая в тексте варианта.** В записи `{ id: a, text: ..., correct: true }` запятая разделяет поля. Если в тексте есть запятая, возьмите его в кавычки:

```yaml
- { id: a, text: "Тот, кто произнёс заклинание", correct: true }
```

### Оформление

Сайт использует «Экзамен С.О.В.»: экзаменационный бланк цвета слоновой кости, сине-чёрные чернила и рукописные пометки преподавателя. Переключателя оформления нет; прежнее поле `theme` в настройках игнорируется.

## Хранение данных в браузере

- `hps-settings-v1` — настройки: «Перемешивать варианты ответов» (`shuffleOptions`), длина теста (`quizLength`).

Повреждённые данные игнорируются, приложение не падает.


## Монстробук

В навигации доступен отдельный раздел `#/monsters` с поиском и страницами существ. Полные карточки сохраняют весь исходный текст, включая биомы, ингредиенты, факты и сценки. Каждый вопрос по Монстробуку показывает изображение соответствующего существа. Вопросы по Монстробуку вынесены в три темы: реакции на магию (294), атаки (76), удержание (48). Вопросы о биомах, луте, сценках и обычном поведении исключены; из поведения используются только условия общения.

Карточки лежат в `content/rules/monster-*.md`, изображения — в `content/assets/monsters/`. При сборке изображения копируются в `public/data/assets/`, который не коммитится. Для повторного импорта исходного файла:

```bash
python scripts/import-monsterbook.py 'Монстробук с картинками финал.md'
npm run content
```

Импорт обновляет карточки и изображения; вопросы редактируются отдельно в YAML. `content/monsterbook.json` содержит имя и SHA-256 исходника, перечень карточек, изображений и контрольные суммы полного текста каждой карточки. Тесты проверяют полноту переноса, наличие изображений, ссылки и отбор вопросов. Файл-источник в корне не требуется для сборки или работы приложения.

Настройки `#/creature-settings` позволяют исключать отдельных существ из всех режимов теста. Флажки сохраняются в браузере; начатая попытка сохраняет свой набор вопросов. Изображение вампира перенесено к началу карточки без изменения исходного текста. Атаки мантикоры проверяются множественным выбором; очевидные вопросы об удержании мелкими существами исключены.

Результаты тестов показываются только для текущей попытки и не сохраняются. Ранее сохранённые результаты удаляются при открытии приложения.

Реплики персонажа хранятся в [content/reactions.yaml](content/reactions.yaml): `success` — похвала за правильный ответ, `failure` — насмешки за ошибку. В каждом наборе изначально по 100 реплик; строки можно редактировать и удалять. Пустой набор (`[]`) отключает соответствующие реплики. После редактирования выполните `npm run content` или сборку. При новом ответе реплика с фотографией и облачком появляется с вероятностью 33% на 3 секунды. В режиме обучения и при повторном просмотре ответов она не появляется. Изображения персонажей находятся в `content/assets/characters/`; все JPG/JPEG/PNG/WebP из этого каталога автоматически включаются в случайный выбор при генерации контента. Персонаж с облачком показывается увеличенным поверх разбора, не меняя размеры блока.
